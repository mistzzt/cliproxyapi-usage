# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. (`CLAUDE.md` is a symlink to `AGENTS.md`; edit `AGENTS.md`.)

## Commands

Dependency manager: `uv` (Python >=3.12; `.python-version` pins 3.14). Frontend uses `bun`. A Nix flake provides a dev shell with both.

- Install deps: `uv sync`
- Run the collector: `uv run cliproxy-usage-collect` (requires `CLIPROXY_MANAGEMENT_KEY`; see README for all env vars). `.envrc` in the repo root (gitignored) exports a working `CLIPROXY_BASE_URL` + key for the upstream dev proxy.
- Run the webapp: `uv run cliproxy-usage-server` (serves `http://127.0.0.1:8318/usage`).
- Frontend commands need `bun`; when it is not on PATH, run them inside the flake dev shell (Python 3.14, uv, bun): `nix develop -c bash -c 'cd frontend && bun test && bun run lint && bun run build'`.
- Frontend dev: `cd frontend && bun install && bun run dev` (Vite on `:5173` proxies `/api` to `:8318`).
- Frontend build: `cd frontend && bun run build` (outputs into `frontend/dist/`).
- Run backend tests: `uv run pytest`
- Single backend test: `uv run pytest tests/test_queue_parser.py::test_name -q`
- Frontend tests: `cd frontend && bun test` (bun:test suites colocated with the pure logic modules they cover)
- Browser tests (Playwright, `e2e/`; builds the frontend first): `nix develop -c bash -c '(cd frontend && bun run build) && python -m pytest e2e -q'`. They need the dev shell's nixpkgs Python (PyPI's Playwright driver cannot start on NixOS); `uv run pytest` does not collect them.
- Lint: `uv run ruff check` / `uv run ruff format`; frontend `cd frontend && bun run lint`
- Type-check: `uv run basedpyright` (config in `pyproject.toml`: `include = ["src", "tests"]`, mode `standard`); frontend type errors, test files included, surface via `bun run build` (`tsc -b`)
- Nix package: `nix build` (builds the frontend into the Python package). Frontend dependency changes must update the x86_64-linux `outputHash` in `flake.nix`.

`test/cpa-usage.tar.gz` (gitignored) is a snapshot of real usage data (`usage.db` + `pricing.json`) for manual testing: extract it outside the repo and point `USAGE_DB_PATH` at it. It holds real API keys and accounts, so never copy anything from it into tests, fixtures, docs, commits, or PR text.

## Architecture

One-shot CLI collector: drains a bounded batch from CLIProxyAPI's HTTP management usage queue and upserts rows into a local SQLite DB. Safe to re-run: dedup is by `timestamp` primary key via `INSERT OR IGNORE`. Designed to be invoked from cron at an interval shorter than the upstream queue retention window; transient failures exit non-zero so cron retries on the next tick.

Data flow (`src/cliproxy_usage_collect/`):

1. `config.py`: `load_config()` reads env (`CLIPROXY_BASE_URL`, `CLIPROXY_MANAGEMENT_KEY`, `USAGE_DB_PATH`, `USAGE_QUEUE_POP_COUNT`, `USAGE_HTTP_TIMEOUT_SECONDS`) via pydantic-settings. `CLIPROXY_BASE_URL` may be either the CLIProxyAPI origin or the management API base URL; default `http://localhost:8317`. `load_settings` (shared with the server) raises `ConfigError` with env-var names (not field names) in the message, and `management_url` builds management API URLs from either form of `CLIPROXY_BASE_URL`.
2. `queue_client.py`: `pop_usage_records(cfg)` uses httpx against the management `usage-queue` endpoint and returns raw JSON queue elements. It authenticates with `CLIPROXY_MANAGEMENT_KEY` as a bearer token, passes the configured count, and maps auth/permission failures to `AuthError`; connection/timeout/protocol/unexpected-response failures to `TransientError`.
3. `parser.py`: `iter_records(queue_elements)` validates each queue JSON element with private strict pydantic models, then yields `RequestRecord`s. Raises `SchemaError` (lives here, not in `schemas.py`) on validation failure.
4. `db.py`: `open_db(path)` creates the `requests` table + indexes if missing. `insert_records` bulk-inserts with `INSERT OR IGNORE` and returns the count of genuinely new rows (via `conn.total_changes` delta).
5. `cli.py`: `main()` wires the above. Exit codes: **0** ok, **1** transient, **2** config, **3** auth, **4** schema. Keep these stable, cron/alerts depend on them.

`schemas.py` holds the _shared_ user-facing shape (`RequestRecord`, frozen). Ingestion-only pydantic models that mirror the proxy's queue JSON stay private to `parser.py`. The server/dashboard consume the SQLite rows generated from `RequestRecord`, so don't move it back into `parser.py` or the DB module.

### Webapp (`src/cliproxy_usage_server/` + `frontend/`)

FastAPI + Vite/React dashboard that reads `usage.db` **read-only** and serves usage/quota JSON endpoints plus the built SPA at `/` (client routes: usage page at `/usage`, limits at `/limits`; `/` and unknown paths redirect to `/usage`). Single-process deployment via `uv run cliproxy-usage-server`. Env vars are documented in README.

- `config.py`: `ServerConfig` via pydantic-settings; loaded with the collector's `load_settings`. `load_key_aliases` reads `USAGE_KEY_ALIASES` (path to a JSON object, redacted key to display name); unset or absent file gives `{}`, malformed content raises `ConfigError`.
- Usage endpoints (`routes/usage.py`, under `/api/usage`): `summary` (KPI totals, previous period, dense `cost`/`input_tokens`/`output_tokens`/`cached_tokens`/`requests` series), `breakdown?dim=person|model|credential` (one row per entity with current/previous totals, `cost`/`input_tokens`/`output_tokens`/`cached_tokens` trend aligned to `buckets`, paired-dimension `mix`: person to model, model and credential to person), `options` (no params; every entity per dimension with `label` and color `slot`).
- Range params (all but `options`): `start` (optional; absent means all time, and then `previous` is `None`), `end` (default now), `tz` (required IANA name), comma-separated `people` (redacted keys), `models`, `credentials` (redacted sources); `summary`/`breakdown` also take `bucket=auto|hour|day|week`. Naive datetimes, `start > end`, and unknown `tz` are 422s. The previous period is the equal-length window ending at `start`. The effective bucket is echoed back.
- `db.py`: `open_ro(path)` via `file:...?mode=ro` URI; viewer-local bucketing in the IANA `tz` (DST aware): day buckets run local midnight to midnight, week buckets start Monday 00:00 local. `auto_bucket` picks hour up to 2 days, day up to 120 days, week beyond; `effective_bucket` coarsens an explicit bucket to the next unit past `MAX_BUCKETS` (1,000). `bucket_starts` builds the dense axis; `SliceIndexer` maps 15-minute UTC slices onto it.
- `aggregate.py`: every endpoint aggregates one grouped query, `_fetch_cells`: rows per (15-minute UTC slice, api_key, model, source). Tiers apply per request, never to sums: the query splits each request's tokens into base-rate and above-rate amounts using its model's `CostPlan` and sums those, so a cell's cost equals the sum of its requests' costs. This query is the only per-request cost implementation; `CostPlan.price` multiplies its sums by the rates. Totals, rows, trends, and mixes are sums of the same cells, so they always agree and cost does not depend on the bucket. Helpers: `query_summary`, `query_breakdown`, `query_options`. All-time axes start at the first recorded request. Rows and mixes sort by cost desc, then tokens desc.
- Tokens everywhere mean input + output (cached excluded); the stored `total_tokens` column is never summed. The API returns only the raw components (`input_tokens`, `output_tokens`, `cached_tokens` in totals, series, trends, and mix entries); the frontend derives tokens with `tokens`/`tokenSeries` in `src/utils/usage/totals.ts`, the single definition. Latency is average only.
- People are API keys redacted with `redact_key` (raw keys that redact alike merge into one person); `label` is the `USAGE_KEY_ALIASES` name or the redacted key as-is. Unmatched alias entries are logged once, the first time `options` runs. Models and credentials use their key as label. Models are keyed and priced by `model_key` (an empty id becomes `<empty>`, which matches no pricing entry). Credentials are sources redacted with `redact_source` (email sources pass through). `resolve_filter` maps display-key filter values (redacted keys, model keys, redacted sources) back to raw column values.
- Color slots: `options` ranks each dimension by all-time spend; the top 7 (`SLOT_COUNT`) get slots 0..6, the rest `None` ("Other"), so colors never change with filters.
- `pricing.py`: hand-ported subset of ccusage's LiteLLM pricing and per-request cost (`ModelPricing`, `resolve`, `cost_plan` deciding each model's rates, threshold and long-context mode, disk cache with TTL). `*_above_200k_tokens` rates are marginal per token type; rates only published above 272k, and every OpenAI-accounting model (ccusage's Codex adapter), bill the whole request at the long rate once its context passes the threshold. Entries without base input and output rates are dropped; missing cache rates fall back as in ccusage. `tests/test_pricing_ccusage.py` pins these semantics by pricing single requests through the production query (`request_cost` in `conftest.py`) against fixed, hand-checked amounts; tests never reimplement cost logic (TODO there: cross-check against ccusage itself). Cache lives at `<db_parent>/pricing.json` by default. Missing pricing is signalled by `cost_status` (`live`/`partial_missing`/`missing`); there is no pricing endpoint. Model breakdown rows carry `price`, the per-1M rates of the same `CostPlan` that priced their cost (base input/output/cache read/write, `long_context` threshold, scope and rates, and `cached_in_input` for OpenAI accounting); `None` when unpriced or not a model row.
- `main.py`: `create_app(config, *, pricing_provider=None, quota_service_factory=None)` + `run()`. Lifespan loads pricing on startup and schedules a background TTL refresh. SPA static mount only happens if `frontend/dist/` exists (so backend-only test runs don't need built assets); unknown `/api/*` paths 404 instead of returning the SPA shell. `/usage-config.js` injects base path, API base, and page title at runtime.
- `quota/`: quota API client, provider parsers, TTL cache, and service layer for Claude/Codex OAuth quota lookups through CLIProxyAPI's management API. Any failure to reach CLIProxyAPI or parse a vendor answer becomes an error envelope for that account only; one `TtlCache` keeps each envelope until its own `stale_at` (errors expire sooner), and the auth-file list is cached too.
- `routes/usage.py`, `routes/quota.py`: each exposes a `build_router(...)` factory included in `main.py` under `/api`.

Shared-schema rule: response DTOs live in `cliproxy_usage_server/schemas.py`. The frontend types in `frontend/src/types/api.ts` are **hand-maintained** to match those DTOs; keep them in sync when backend schemas change.

### Frontend (`frontend/`)

Bun + Vite + React 19 + TypeScript (strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` + `verbatimModuleSyntax`) + Chart.js (registered in `src/components/charts/chart-setup.ts`) + SCSS modules + TanStack Query (all server data) + Zustand (theme store) + react-router v7 + Radix popover + react-day-picker/date-fns for the range calendar. Path alias `@/*` maps to `./src/*`.

- Pages: `src/pages/UsagePage.tsx` (route `/usage`) and `src/pages/QuotaPage.tsx` (route `/limits`), rendered under the layout route `src/components/ui/AppLayout.tsx`: a centered shell capped at `--page-max-width` that owns the side gutters (`--page-gutter`, both in `src/styles/global.scss`) and draws the shared top bar (`src/components/ui/AppHeader.tsx`), sticky at `--app-header-height`, which the sticky `FilterBar` sits below. The page always reserves its scrollbar gutter so switching pages never shifts the layout. Pages and their components never add their own horizontal page padding or width cap. API clients in `src/services/` (`api.ts`: `apiFetch`/`getJson` throw `ApiError` with the server's `detail` for every endpoint, `getUsage` fetches the request a query key names, `getOptions`; `quotaApi.ts`). The Limits page (`src/hooks/useQuotaQueries.ts`) queries the accounts and each account's quota, fetched again on every visit (failed ones included, never on focus); the reset mutation settles once that account's quota is refetched. `QuotaCard` stays presentational; `resetState` in `src/utils/quota.ts` (with `PROVIDER_LABEL`) derives its reset control from the card's confirmation flag and the mutation.
- Usage data loading (`src/hooks/useUsageQueries.ts`, keys in `src/utils/usage/queryKeys.ts`, client in `src/services/queryClient.ts`): `useUsageWindow` turns the picked range into a `ResolvedWindow` (ISO `start`/`end` + `tz`) in a browser-only query keyed by range and tz; it is the only place a request's window reads the current time. Its entry is removed once nothing shows it, so re-picking a range or revisiting the page computes a fresh window. Every request (`useUsage`) keys on `['usage', window, endpoint, params]`, so all panels and the drawer share one window and a range change fetches each panel once. Responses never expire, refetch on focus, or retry; the page fetches only for a new key or Refresh, which recomputes the window, refetches the shown requests (hidden ones in the same window when next shown) and the options. While a key loads, panels keep the previous key's data dimmed with `aria-busy` (`src/components/ui/Busy.module.scss`); a failed request shows its failure note, never older data. Panels render through `src/components/ui/Loaded.tsx` (a failure note, data, or a spinner); `src/components/ui/FailureBanner.tsx` names each failed request on the page and in the drawer. Message boxes share `src/components/ui/Banner.module.scss`, buttons use `src/components/ui/Button.tsx`, and `.muted`/`.swatch` come from `src/components/usage/Shared.module.scss`.
- Usage page, top to bottom: sticky `FilterBar` (range presets or custom date+time, people/models/credentials multi-selects, granularity labeled with the bucket the server actually used (Auto names it only while selected), metric cost/tokens), `KpiStrip` (spend, tokens, requests, failure rate, avg latency, change vs previous period), "People by {metric}" (`ShareBar` + `RichRows`), `Heatmap` (people x models, built from the person breakdown's `mix`, so it loads and fails with the people panel), Models/Credentials tabs (`ShareBar` + `RichRows`), and `DetailDrawer` (opened from any row, segment, or heatmap row; calls `summary`/`breakdown` with the entity added to the filters; "Filter page to this" applies it). Components live in `src/components/usage/`; `TimeChart.tsx` is the Chart.js stacked bar chart.
- `RichRows` is generic over dimension: share, spend, tokens, change, trend strip with shared hover bucket, mix bar, failure rate; models add cache hit rate (convention from `price.cached_in_input`, never guessed from the model name), the price cost is computed with, latency; credentials add last used.
- Pure logic lives in `src/utils/usage/*.ts` with colocated `*.test.ts` (bun:test): `range` (presets, custom windows, whole-day calendar picks capped at now, `pickDay` so each click pair starts a fresh range, `resolveWindow` at a given now, `viewerTimeZone()`), `queryKeys` (window resolution, request keys, `requestParams`, `windowPrefix`), `viewState` (URL parse/serialize, `scopeToEntity`, `granularityOptions`), `format`, `dates`, `modelNames` (short names, families), `palette` (7 light + 7 dark slots plus Other gray), `entities` (label/slot lookup from `options`), `share` (`shareItems` from a breakdown, Other folding), `stack` (`breakdownChart` for the drawer's over-time chart), `richRows` (row derivation, mix sorting, sort state), `heatmap` (`personModelCells` from the person breakdown, column selection, bins), `price`, `totals` (failure and cache hit rates, `tokens`/`tokenSeries`). Keep new chart/state logic in this testable pure-module style rather than inside components.
- View state (range, filters, granularity, metric, tab, open drawer) lives in the URL query string via `src/hooks/useUsageViewState.ts`; a load with no query string restores localStorage key `usage.view.v1`. The browser's IANA timezone is sent as `tz` on every range request.
- Every place the UI names an entity uses the server `label` (model ids shortened by `modelNames` for display); colors come from `options` slots, never from filtered ranks.

Authentication is delegated to an upstream reverse proxy; the app itself exposes `/api/*` without access control.

## Tests

- `tests/`: pytest suite; JSON fixtures live in `tests/fixtures/`. `conftest.py` exposes the quota api-call fixtures and `synthetic_db_path` (multi-person, multi-model, spans the 2026-11-01 DST change in `America/Chicago`) for server tests; `write_usage_db` builds custom DBs, and `request_cost` prices one request through the production query. Cost tests compare against fixed, hand-checked amounts and never reimplement cost logic. Test data is synthetic only (see the `test/cpa-usage.tar.gz` note above).
- `test_queue_client.py` uses `httpx.MockTransport`; prefer that over a real CLIProxyAPI process.
- Frontend tests are bun:test, colocated with the modules they test.
- `e2e/`: Playwright browser tests (pytest). The Limits test fakes the quota endpoints with `page.route` (reset, then refetch; reload on revisit). The usage page tests cover its requests: one per visible panel on a range change, Refresh, fresh windows on revisit, a shared window with the drawer, tab caching, per-panel failures (a failed person breakdown fails the people panel and the heatmap together), and busy panels keeping rows. The dev shell's Python lacks the project packages, so project code runs only through `uv run` subprocesses: `seed_db.py` writes a synthetic DB with timestamps relative to now, and the fixtures start `cliproxy-usage-server` on it.

## Conventions

- Ruff target is `py314`; basedpyright `pythonVersion = "3.14"`. Code must stay compatible with that even though `requires-python` is `>=3.12`.
- No migration / backward-compat shims unless explicitly asked (this is a greenfield project).
- The SQLite schema in the collector's `db.py` is authoritative; if you change column order, update `_INSERT`'s positional `VALUES (?,...)` in lockstep.
